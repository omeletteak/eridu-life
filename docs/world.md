# 世界と道（複数人で遊ぶための設計）

`lab/` で試している仕組み。表の形は `docs/schema.md`。やることは GitHub の issue に置く。

## 考え方
世界は先に決まっている。プレイヤーは選択をしているように見えるが、選べる道は
最初から全部あり、その中の一本を歩くだけ。歩いた道にだけ、誰が・いつ・どの版で
歩いたかが残る。

- シーズン・版・時代・住民番号から、その人の生まれ（名前・地区・シリオンか・
  適性）と運命（1年ごとの乱数）が決まる（`js/sim.js` の fate）。同じ番号なら
  誰が遊んでも同じ赤ちゃんが生まれる
- 運命は番号と年齢で決まる。選択を変えても「その年に起きる運命」は同じで、
  受け止め方が変わる
- 同じ番号で同じ選択をすれば、必ず同じ一生になる（`tools/fate.js` で確かめる）

## 住民番号と同じ1秒
- 番号はシーズンごとに 100000〜999999。5つずつの組に分かれ、同じ組の5人が
  「同じ1秒に生まれた人たち」。陥落に遭う年齢も組で決まる
- 本人の番号は、まだ歩かれていない番号のいちばん小さいもの（生まれる場所を
  選んだら、そこに生まれる番号）
- 20% は、もう誰かが歩いた番号に生まれる（同じ人をもう一度生きる）。同じ選択を
  すれば前の人の道をなぞり、違う選択をすれば、そこで初めての分かれ道ができる
- 同じ組の4人は、歩かれた番号なら、いちばん早く歩き終えた人の道をたどる。
  誰も歩いていなければ運命が選ぶ道を行く。どちらかは見た目で区別しない

## 道が確定するのは最期
- 道は最後の選択まで決まらない。記録は亡くなったときに書く。遊びかけの一生は
  残らず、誰の世界にも出てこない
- 同じ番号をまったく同じ道で歩いた人がまだいなければ、最期の画面と前世の記録で
  住民番号の横に ✦ を出す（その道に名前が付いた印。説明はしない）
- 2人が同じ番号をまったく同じ順に選ぶ確率は、いまの時代で約2%、陥落の前で
  約7%（ほとんどは早く亡くなった短い道）。決断を6回以上した一生では数百回に1回

## 気付かせ方
自分以外は NPC に見えるが、しばらく遊ぶと「全員が NPC ではない…？」と気付く。
明言はしない。

- 住民番号は、亡くなるまで存在ごと出さない
- 「ほかのプレイヤー」の印は出さない
- 手がかり：同じ名前の人が同じ一生で何度も現れる／前世の記録の名前が4人の中に
  いる／✦ がふだん付いていて、まれに付かない

## シーズンと版
- 番号を使い切るか、版（`E.VERSION`）が変わったら次のシーズンを始める（ワイプ）。
  前のシーズンの行は消さない
- 版は、動き（確率・効果・決断・乱数を引く順番）を変えたら上げる。版が違うと
  同じ道でも結果が変わるため。上げ忘れは `tools/fate.js` が止める
- 記録の文や選択肢のラベルだけの変更は版を上げなくてよい。選択肢の ID は追記だけ

## 共有するもの
- 送り合うのは「シーズン・版・時代・番号・道」だけ（1件 100 バイトほど）。
  毎年の状態は番号と道から作り直せる
- 受け取った道は、形（決まった ID だけか）を確かめ、サーバーでたどり直して
  確かめられる（ありえない道や改ざんを見抜ける）
- 端末から SQL は受け取らない。SQL はサーバー側でプレースホルダを使って組む
- 健康などの細かい数は、ブラウザによって最後の桁が違うことがあるので、
  確かめるときは選択・年齢・死因で比べる

## 開発用
- `lab/?ids=N`：1シーズンを N 人にする（ワイプの確認）
- `lab/?reborn=1`：必ず歩かれた番号に生まれる
- `lab/?sql`：画面の下に SQL の欄を出す
- `lab/?fall…`：番号を使わずにいつもどおり生まれ、記録も残さない
- `lab/?local`：Worker から開いても、サーバーにつながず端末の表だけで遊ぶ
  （Worker から開いた lab は、番号と同じ1秒の道をサーバーからもらう。`docs/worker.md`）
